# 2026-09-15 · 迁移后收集「题数」显示异常（jsonb 列被存成字符串）

## 病状
环境迁移后，收集列表的题数显示为 **`112 道题` / `205 道题`**（该问卷实际只有 1 / 2 题）。

## 排查
1. 页面 HTML 里确实是 `<span>112 道题</span>`，代码为 `((s.questions || []).length) + " 道题"`。
2. 查库：`select jsonb_typeof(questions) from surveys` → **`string`**（不是 `array`）。
3. 即 `questions` 是**字符串**，`.length` 取到的是 JSON 文本长度（112/205），故显示荒谬数字。

## 根因
环境迁移时用 CLI `tcb db execute --json "SELECT * FROM <t>"` 导出：**每个单元格被序列化成字符串**（如 `"[\"{...}\"]"`）。
我在重建行对象时把该字符串原样写入，导致 **jsonb 列在新环境变成了字符串标量**。

影响列（迁移时全部中招）：

| 表.列 | 行数 |
|---|---|
| `surveys.questions` | 2 |
| `notices.attachments` | 2 |
| `notices.links` | 2 |
| `survey_responses.answers` | 43 |

## 修复
逐列「字符串 → jsonb」还原：

```sql
update public.<表> set <列> = (<列> #>> '{}')::jsonb where jsonb_typeof(<列>) = 'string';
```

对 4 个列执行后，`jsonb_typeof` 全部变回 **`array`**；UI 题数恢复为 `1 道题 / 2 道题`，收集统计（票数/百分比/文本回答/未交名单）与通知置顶徽标均正常。

## 教训（下次迁移照做）
1. 跨环境搬 **jsonb/json** 数据，不要走「把每个单元格当字符串拼回」的通道；优先 `pg_dump` 或 PostgREST 原生 JSON body。
2. 迁移后**必校验**：`select jsonb_typeof(<列>)` 对所有 jsonb 列应为 `array|object`，不得为 `string`。
3. 迁移脚本应把「JSON 文本 → jsonb」的还原作为固定步骤。

## 附带发现（非 bug）
`survey_anonymous_responses` 开了 RLS 但**没有 policy**，是有意设计：该表通过 `SECURITY DEFINER` 函数（`app.submit_anonymous` / `app.my_anonymous` / `app.anon_summary`）访问，客户端不直连。
