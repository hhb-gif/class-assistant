# 2026-09-15 · PG 迁移执行器按分号切分，函数体被截断（SQLSTATE 42601）

## 症状

新增匿名收集迁移 `20260915010300_survey_anonymous.sql`（含 4 个 PL/pgSQL 函数），
`managePgDatabase(action=applyMigration)` 报：

```
execute migration 20260915010300 stmt#10:
ERROR: syntax error at end of input (SQLSTATE 42601)
```

- `stmt#10` 恰好是**第一个函数体内含分号的函数**（`app.anon_gen_id()`，体里有两条 `return ...;`）。
- 前 9 条语句（建表 / 索引 / 建 schema / 授权）本身在 `$$` 外，正常。
- 失败后复查：**什么都没落地**（表、schema、函数全为 0）→ 迁移走事务，失败整体回滚，环境干净。

## 排查

1. 对照已有能成功的迁移 `20260914181200_phase_a_core_tables.sql` 与 `20260914200000`：
   它们的 `app.is_admin()` / `app.my_member_id()` 也是 `$$` 函数，但**函数体内没有分号**
   （单条 `select exists(...)`）。→ 说明执行器不是「不认识 `$$`」，而是**按 `;` 切分语句**。
2. `stmt#10` 的行号定位与上述推断完全吻合：`anon_hash()`（体内无分号）能过，
   `anon_gen_id()`（体内两条 return）被截断成
   `... as $$ begin return 'ar_' || replace(gen_random_uuid()::text, '-'`
   →「syntax error at end of input」。

结论：**迁移执行器不支持多语句 PL/pgSQL 函数体**（`$$` 内的 `;` 会被当作语句分隔符）。

## 修复

把 4 个函数全部改写为 `language sql` 的**单条语句**形式，函数体内一个分号都不出现：

| 函数 | 改写方式 |
|------|----------|
| `app.anon_hash` | 本来就是单语句，未动 |
| `app.anon_gen_id` | 去掉 `begin/exception/end` 兜底（PG13+ 内置 `gen_random_uuid()`），单条 `select` |
| `app.submit_anonymous` | `CASE` 归一化所有校验分支 → `WITH err AS (...), ins AS (INSERT ... ON CONFLICT ... RETURNING)` + `UNION ALL` 两分支产出 `{ok:true}` / `{ok:false,code}` |
| `app.my_anonymous` | `CASE` + 一个 scalar 子查询，单条 `select` |
| `app.anon_summary` | `CASE` 外层做校验；`else` 分支内嵌 `WITH flat AS (...)`，用 `jsonb_array_elements_text` 把标量/数组统一摊平成「一行一个值」，再按 `qid` 聚合 |

- 关键点：`submit_anonymous` 的写入用 **data-modifying CTE**，函数必须是 `VOLATILE`（SQL 函数允许；
  `STABLE`/`IMMUTABLE` 不允许写库）。
- `public.*` 的 RPC 包装层本来就是单语句，无需改。
- 迁移版本号沿用 `20260915010300`（上次终态失败且未落地，版本号未被占用）。
  注：在此之前 `20260915010200_class_materials` 已先应用，导致 `...10100` 被判为
  「older than latest remote」不可执行 → 顺手把匿名迁移重编号为 `...10300`。

## 验证

- `applyMigration` 返回 `Status: Succeed`、`verified: true`。
- 复查 `pg_proc`：`app` 下 5 个函数 + `public` 下 3 个包装层全部存在；
  `submit_anonymous` = `v`（volatile），其余 = `s`（stable），`prosecdef=true`（除包装层）。
- 权限守卫实测（管理连接 `auth.uid()` 为 null）：
  `submit_anonymous / my_anonymous / anon_summary` 均返回
  `{"ok": false, "code": "NOT_AUTHENTICATED"}` ✅
- `anon_hash` 同输入稳定、不同输入不同；`anon_gen_id()` 长度 35（`ar_` + 32 hex）✅
- 聚合逻辑：人工插入 3 条匿名答案（2×「周五下午第三节」、1×「周一早读」）后跑聚合 SQL，
  得到 `submitted: 3`、`counts: {"周五下午第三节": 2, "周一早读": 1}`、`texts: []` ✅
  验证后已删除测试数据。

## 遗留 / 未验证

- 未在**真实浏览器会话**下验证 PostgREST `rpc()`（浏览器侧 `db.rpc("submit_anonymous", {...})`
  的返回形状、`public` schema 暴露情况）；已加 `public` 包装层兜底，仍需真机点一次。
- 「启用 RLS + 零策略 = deny all」这一条是 PostgreSQL 的既有语义，未在 authenticated 角色下实测
  （管理连接绕过 RLS，测不出）。
- `md5` 加盐而非 sha256：为免 `pgcrypto` 扩展依赖；token 是随机串不是口令，强度足够。

## 教训（写进约定）

> **本项目 PG 迁移里的函数体必须是单条 SQL 语句**（`language sql`），
> 或至少保证 `$$ ... $$` 内**不出现分号**。
> 需要多语句逻辑时，用 `CASE` / CTE / 子查询表达，不要写 `BEGIN ... END` 的 PL/pgSQL。
