# 2026-09-14 · 微信打开「子域」变成下载 / 真实浏览器打不开

## 病状
- 微信内打开 `https://app-class-assistant-…webapps.tcloudbase.com/`：**不显示网页，反而下载文件**。
- 用户反馈子域「打不开」（真实浏览器）。

## 排查
1. `curl -sI` 各路径（`/`、`/index.html`、`/src/cloud.js`、`/styles.css`、`/assets/*.png`）——**全部**返回：
   ```
   content-type: text/html        (或对应类型)
   content-disposition: attachment
   ```
   → 全站被强制「下载」。
2. 模拟浏览器导航（加 `Sec-Fetch-Mode: navigate`）——返回 **404** + HTML 体（拦截页）。
3. 普通请求（无该头，微信/curl 等同理）——`200` + `attachment`。

## 根因（平台政策，非本项目缺陷）
CloudBase 官方文档《默认域名访问限制及中间页》（https://docs.cloudbase.net/service/alias）：
> 云开发「默认域名」（`*.tcloudbaseapp.com`、`*.run.tcloudbase.com`、`*.app.tcloudbase.com` 等）**仅建议用于开发测试**。浏览器直接访问（`Sec-Fetch-Mode: navigate`）会展示「访问提示中间页」；**其他请求会添加 `Content-Disposition: attachment`**。
> **移除中间页的唯一合规途径是配置并使用自定义域名**（自定义域名必须完成 **ICP 备案**）。
> 默认域名可能因流量触发风控而被关停，**生产务必用自定义域名**。

即：**微信内请求未带 `navigate` 语义 → 命中 attachment → 下载**；**真实浏览器导航 → 命中中间页 → 表现为「打不开」**。

## 为什么此前误判「可访问」
`opencli` 的浏览器桥发起导航时**不带 `Sec-Fetch-Mode: navigate`**，因此拿到 200（attachment 被其忽略）并正常渲染；我用它验证过登录，误以为对外可用。**桌面真实浏览器/微信均会命中限制。**

## 结论
- 不是部署或代码问题；**默认域名不可用于对外分发**。
- 三个地址（`*.tcloudbaseapp.com` ×1、`*.webapps.tcloudbase.com` ×2）**同样受限**。

## 解决方案
| 方案 | 可行性 |
|------|--------|
| **绑定自定义域名**（自有域名 + ICP 备案） | ✅ **唯一合规解**；体验版可能不支持绑定（需评估升级套餐）；开发阶段可先在腾讯云做备案 |
| 换其它默认域名 | ❌ 同样受限 |
| 云函数/云托管临时域名 | ❌ 同属默认域名，同样受限 |
